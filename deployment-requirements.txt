3. HOW TO GENERATE YOUR OWN SECRETS (do this yourself, on your computer)
======================================================================
Run each command in a terminal, copy the output straight into Railway, then into your password manager.
Generate DIFFERENT values for staging and production.

SESSION_SECRET            openssl rand -base64 48
BLIND_INDEX_KEY           openssl rand -base64 32
FIELD_ENCRYPTION_KEYS     openssl rand -base64 32      then wrap it like this:  {"k1":"PASTE_VALUE_HERE"}
FIELD_ENCRYPTION_ACTIVE_KID   k1
DATABASE_APP_USER_PASSWORD    openssl rand -base64 32
Backup encryption key pair (age):
    install age (https://age-encryption.org), then run:   age-keygen -o backup-private.key
    - The line "public key: age1...." goes into BACKUP_AGE_PUBLIC_KEY  [PUBLIC]
    - backup-private.key NEVER goes online. Store it in your password manager + an offline copy.
      You need it only to restore a backup.

IMPORTANT: losing FIELD_ENCRYPTION_KEYS means encrypted NI / passport / bank fields cannot be read.
Back them up in the password manager before first use.

======================================================================
PLATFORM_SSR_SECRET       Separate random secret >=32 characters, identical on web and API only.
PLATFORM_INGRESS_SECRET   Different random secret >=32 characters, on web and trusted edge only.

Admin SSR ingress contract (required before enabling admin pages):
- Restrict the web origin to your trusted edge (private networking/firewall or authenticated origin).
- On EVERY request to the admin web host, the edge MUST overwrite X-Platform-Ingress-Key with
  PLATFORM_INGRESS_SECRET and X-Platform-Visitor-IP with the verified visitor IP. Strip incoming
  values even when present. With Cloudflare, use the connection visitor IP (ip.src), not a client
  forwarding header; a further proxy must authenticate its upstream before vouching for identity.
- Never return the ingress key in responses or expose either secret through NEXT_PUBLIC_*.
- The web server refuses SSR data access without valid ingress identity and both configured keys.
  The API verifies a 30-second HMAC assertion bound to GET URL and cookies, then applies the same
  ADMIN_IP_ALLOWLIST and audits the visitor IP/user agent. Browser actions retain the existing
  trusted-proxy identity rules. Adding the web server IP to the allowlist is not a substitute.
- Rotate each secret at both of its holders together. Configure and verify staging first.

---- 5.1 Cloudflare --------------------------------------------------------------------------
[ ] Add the domain; change nameservers at your registrar to Cloudflare's.
[ ] SSL/TLS mode: Full (strict). Always Use HTTPS: on. Min TLS 1.2. HSTS: on (after go-live works).
[ ] WAF: Managed rules on. Bot Fight Mode on.

[ ] DNS records (all proxied/orange cloud), values come from Railway "Custom domain" screens:
      yourdomain            CNAME  -> production web Railway target
      www                   CNAME  -> production web Railway target (redirect www -> root in web)
      api                   CNAME  -> production api Railway target
      admin                 CNAME  -> production web Railway target
      staging               CNAME  -> staging web target
      api.staging           CNAME  -> staging api target
      admin.staging         CNAME  -> staging web target
      + any TXT verification records Railway asks for
[ ] R2: create buckets with EU jurisdiction:
      brand-prod-files, brand-prod-backups, brand-staging-files, brand-staging-backups
      Public access: OFF on all. No public r2.dev URL.
[ ] R2 API tokens (Object Read & Write), each restricted to ONE bucket:
      token 1 -> brand-prod-files        (R2_ACCESS_KEY_ID / R2_SECRET_ACCESS_KEY, production)
      token 2 -> brand-prod-backups      (R2_BACKUP_* , production)
      token 3 -> brand-staging-files     (staging)
      token 4 -> brand-staging-backups   (staging)
[ ] Turnstile: add a widget (Managed mode) for domains yourdomain + staging.yourdomain
