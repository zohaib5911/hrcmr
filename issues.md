# Project review findings

Reviewed dev commit `9ae5296`. This is a static review of the repository, with targeted tracing through the web client, API, background workers, storage and CI. Ruff's security rules passed on `api/app`. Runtime behavior, deployed configuration, dependency advisories and peak memory were not independently tested. Priority reflects potential impact. Three findings already have candidate fixes in the local `task/FIX-security-audit` branch at `d3aaa71`.

## High priority

| Issue and source | Why it matters | Proposed fix and acceptance check |
|---|---|---|
| **Session refresh can undo revocation.** `api/app/modules/auth/sessions.py:110`, `:161`, `:168`, `:223` | Refresh reads a Redis session and later writes its entire value back. If revocation deletes the key in between, the write recreates it. A revoked session can consequently remain usable. | The security branch already changes refresh to update expiry only on an existing key and patches individual fields atomically. Verify revocation remains final when refresh and privilege updates overlap. |
| **Retention can delete evidence while its database records survive.** `api/app/jobs/retention.py:54`, `:145`, `:159` | The worker deletes object bytes before its transaction commits. A later failure rolls back the metadata for previously processed files, leaving evidence references that can no longer be downloaded. | The security branch moves physical deletion to the orphan sweep. Verify that a rollback preserves readable evidence and that a successful commit eventually removes the object. |
| **Company export CSVs can interpret user text as formulas.** `api/app/modules/exports/archive.py:97`, `:101`, `:180`, `:193` | Uploaded filenames and table values are written directly to spreadsheet cells. CSV quoting protects the file structure but spreadsheet software can still evaluate untrusted text when an administrator opens the export. | The security branch adds cell sanitization at the shared writer. Verify both table CSVs and the document index render formula-like filenames and free text literally in supported spreadsheet readers. |

## Medium priority

| Issue and source | Why it matters | Proposed fix and acceptance check |
|---|---|---|
| **The staging scanner accepts hosts outside the project.** `.github/workflows/security.yml:65`, `:72`, `:89` | The workflow tests for a staging label anywhere in a manually supplied host. That label conveys no ownership, so a mistyped or unrelated host can pass the guard and receive scan traffic. | Parse the URL and require its HTTPS origin to match an explicit repository-controlled allowlist. Reject user information and keep crawl scope within approved origins. Unit-test the validator offline with approved and unrelated hostnames. |
| **Large employers cannot select every eligible reporting or leave authority.** `web/components/employees/employment-tab.tsx:159`, `:406`, `:476`; `api/app/modules/employees/router.py:51`, `:137` | The editor fills both selectors from one unfiltered directory request capped at 2,000 people. Someone outside that result cannot be chosen. Merely opening the tab also loads the directory and constructs lookup data for a form the user may never open. | Load a permission-scoped, server-searchable picker when the form opens. Resolve the current selection by ID. Verify an eligible employee beyond the first 2,000 can be found and saved. |
| **Changing audit logs can produce duplicated or omitted CSV rows.** `api/app/modules/audit/router.py:163`, `:171`; `api/app/modules/platform_admin/audit_log.py:116`, `:124` | Each exporter advances an offset over newest-first records. With PostgreSQL's default read-committed isolation, new events can shift page boundaries between queries. Later pages also force the database to skip increasingly large prefixes. | Reuse the tenant list's composite cursor at `api/app/modules/audit/router.py:122` for both exports. Use a consistent snapshot if the export promises point-in-time completeness. Compare exported IDs with the starting snapshot while new events arrive. |
| **Company archive generation buffers a tenant's entire table.** `api/app/modules/exports/archive.py:135`, `:152`, `:166`, `:191` | The worker materializes SQL results, formatted rows and an encoded CSV. It also retains the document list and index rows. A large attendance or audit history can exhaust worker memory even when the final ZIP is written to disk. | Stream database rows in batches into writable ZIP entries, spool the document index, and read document bytes in chunks. Compare output and peak worker memory across progressively larger exports. |
| **The daily retention worker locks every dated leaver before checking eligibility.** `api/app/jobs/retention.py:64`, `:72`, `:97`, `:159` | Even recent leavers trigger per-person work. Locks and transaction state accumulate across tenants until the final commit, increasing contention with employee updates and increasing the amount retried after a failure. | Preselect eligible candidates with indexed dates and remaining evidence, preserve visa and leap-day rules, and process stable batches in short transactions. Verify equivalent retention outcomes and measure query count and lock duration on a large tenant. |

## Lower priority

| Issue and source | Why it matters | Proposed fix and acceptance check |
|---|---|---|
| **A nearly expired rate limit can advertise a whole new waiting window.** `api/app/core/rate_limit.py:37`, `:52`, `:61` | Redis can return a TTL of zero during the final fraction of a second. The fallback substitutes the entire window, which can tell a user to wait another hour for an account limit that is about to clear. | Return at least one second for a valid TTL and handle missing expiry separately. Check the retry delay when the script returns zero. |
| **Parallel first-load requests repeat CSRF bootstrap work.** `web/lib/auth/request.ts:104`, `:105`, `:116`; `web/components/employees/employment-tab.tsx:155` | Before the first cookie arrives, concurrent calls each issue a credentialed health request and wait for its body. This adds avoidable API traffic on initial load. | Share one in-flight bootstrap promise per API origin and clear it after completion or failure. Check that concurrent calls with an empty cookie jar trigger one bootstrap and that a later attempt can retry a failed bootstrap. |
